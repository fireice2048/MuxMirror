# 鸿蒙服务器列表拖动排序设计

日期：2026-07-22
状态：已确认

## 目标

- 首页服务器列表项可通过长按后上下拖动调整顺序。
- 拖动中选中项浮起并跟手，其他项自动让位。
- 拖动完成后持久化新顺序，App 重启后保持。
- 缩减列表项右侧三个操作按钮的水平占用宽度。

## 方案

使用 ArkUI 原生 `ForEach.onMove` 拖拽排序。该能力在 `List` 下为 `ListItem` 提供长按、跟手移动和落位动画，不自行实现手势竞争或拖拽坐标计算。

不给 `ServerProfile` 新增排序字段。`servers.yaml` 已以数组顺序表示展示顺序，只需移动数组元素并整体写回。

## 组件与数据流

1. `ServerListPage` 在 `ForEach` 上注册 `onMove`，并通过新增的 `onReorder(from, to)` 回调把移动请求交给父组件。
2. 长按后由 ArkUI 原生排序效果让目标卡片浮起跟手；松手后自动落位。
3. `Index` 处理 `onReorder(from, to)`：调整自身持有的服务器数组顺序，同时调用新增的 `moveConfig(from, to)`。`ServerListPage` 不直接修改 `@Prop` 数据。
4. ArkTS 薄封装调用 NAPI 新增接口 `tmConfigMove(from, to)`。Rust 配置存储校验索引、移动元素并把整个数组写回 `servers.yaml`。
5. 持久化成功时保留新顺序；失败时恢复 Rust 内存中的原顺序，UI 重新加载已持久化顺序。

FFI 只新增接口，不修改现有签名。

## 交互细节

- 整张服务器卡片是长按拖动区域，不增加拖动手柄。
- 普通点击卡片仍打开终端，编辑、复制、删除按钮行为不变。
- 拖动中由 ArkUI 原生排序提供浮起跟手和让位反馈，不使用仅 API 20 可用的拖动事件回调。
- 从索引与目标索引相同时不写磁盘。
- 编辑、复制、删除按钮的宽度从 46vp 调整为 40vp，高度和图标尺寸保持不变。

## 错误处理

- Rust 拒绝越界索引，不改变内存或文件。
- YAML 写入失败时，Rust 恢复移动前的数组，并记录错误日志。
- `tmConfigMove` 返回成功与否；ArkTS 收到失败结果后重新读取配置，保证界面与磁盘一致。

## 验证

- Rust 单元测试：中间项前移、后移、同位置不变、越界拒绝、落盘后重新初始化顺序不变。
- 构建验证：`MobileApp/shared/scripts/build-ohos.sh` 和 `MobileApp/harmonyApp/devecocli build`。
- 人工验收：在鸿蒙模拟器上长按卡片，确认浮起、跟手、让位和落位效果；强制结束并重启 App，确认顺序保留；确认三个操作按钮更紧凑且仍可点击。

## 非目标

- 不增加手动排序模式或上移/下移按钮。
- 不增加 `sortOrder` 配置字段。
- 不实现自定义拖拽手势和坐标计算。
