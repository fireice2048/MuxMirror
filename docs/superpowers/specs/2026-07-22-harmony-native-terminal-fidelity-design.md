# 鸿蒙原生终端显示与输入修复设计

## 决策

继续使用 ArkUI `Text/Span` 原生终端。此次只补齐当前问题所需的终端语义：光标定位、ANSI 弱化样式、有限滚动历史、稳定行数和正确的 IME/退格输入；不重新引入 WebView，也不实现完整 ANSI 主题。

## 架构

### Rust 终端状态

`TerminalBuffer` 仍是输出真相源。备用屏单元格在字符之外保存是否弱化，处理 SGR `2`、`22`、重置以及常见灰色前景色；渲染时合并连续同样式字符为紧凑区间。事件继续携带完整文本快照，同时增加样式区间与 UTF-16 光标偏移。

光标偏移按“光标前实际字符串”的 UTF-16 长度计算。光标所在空白行必须保留，行内至少保留到光标列，避免裁剪空格后把光标移动到已有文字末尾。

备用屏仅在发生真实上滚时把移出的行加入有界历史，清屏和原地重绘不会制造历史。历史容量沿用现有 256KB 快照上限，不新增用户配置。

### ArkTS 渲染

`TerminalNativeView` 根据样式区间构建普通 Span 与灰色 Span，并在远端光标位置插入本地预编辑文字和闪烁光标。存在预编辑文字时，不渲染光标后同一行的 PlaceHolder 部分；远端下一次重绘后恢复正常内容。

滚动组件记录是否处于底部。新输出只在“当前已在底部”时滚到底部；用户手势上滑后保持当前位置，直到收到到达底部事件。

文本字号、显式行高和 PTY 行数计算共享常量。计算结果减 1 行安全余量，最低行数约束保持不变。

### 输入

隐藏 `TextInput` 使用受控文本状态，并读取 `onChange(value, previewText)`：

- `previewText` 仅更新本地预览，不调用 `onInput`；
- 正文新增部分立即调用 `onInput`；
- 正文删除转换为等量远端 Backspace；
- 回车、方向键、Tab、Esc 等继续使用现有编码函数；
- 输入框保留一个不可见哨兵，删除哨兵时发送远端 Backspace 并恢复哨兵，保证远端已有输入也能删除。

本地不再维护整行待发送缓冲。最终显示以远端回显为准，避免本地文字与电脑终端状态分叉。

## 数据契约

`output` 事件保留 `data` 与 `cursor`，新增可选样式区间数组。每个区间使用 UTF-16 起止偏移和枚举样式 `dim`，旧事件或无样式时按当前绿色渲染。NAPI 只负责字段透传，不解释样式。

## 错误与兼容

- 样式区间越界时 ArkTS 钳到快照范围，避免渲染崩溃。
- 不认识的 ANSI 样式继续忽略。
- 没有 `cursor` 或样式字段时保持旧的纯文本末尾光标行为。
- 主屏保留现有线性快照与 256KB 截断行为。

## 测试

Rust 单元测试覆盖：emoji 后 UTF-16 光标、空白行/空格中的光标、SGR 弱化区间、备用屏真实上滚历史和清屏不生成历史。

ArkTS 通过全量构建检查事件类型、Span 渲染和 IME 回调签名。模拟器现场验收覆盖 PlaceHolder、英文/中文预编辑、远端回显、远端 Backspace、手势历史、回到底部恢复跟随以及底部行数。

## 取舍

本设计不追求完整终端模拟器。若后续明确要求 256 色、真彩色、背景色、下划线或超链接，再独立扩展样式模型；当前只实现用户确认需要的弱化文字。
