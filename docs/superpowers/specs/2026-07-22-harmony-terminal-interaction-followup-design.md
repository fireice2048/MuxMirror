# 鸿蒙终端交互补充修复设计

## 范围

本轮只修复四项现场问题：手势滚动、软键盘显隐、键盘按钮图标、已有输入时的光标偏移，以及全宽横线折行残留。继续使用 Rust 终端缓冲和 ArkUI 原生 `Text/Span`，不引入 WebView 或新依赖。

## 设计

### 滚动

终端内容仍由现有 `Scroll` 和 `Scroller` 承载。移除终端外层用于唤起键盘的点击手势，避免它与 Scroll 的拖动识别竞争；显式设置纵向滚动和滚动交互。键盘改由工具条按钮负责拉起。

### 键盘

`TerminalViewController.focus` 先请求隐藏 `TextInput` 获焦，再调用系统 `inputMethod.getController().showTextInput()`。这样即使输入框已经处于焦点状态、键盘曾被系统收起，也能重新进入文本编辑状态。隐藏继续使用现有 `hideTextInput()`。

工具条 `KBD` 项直接显示用户提供的 `keyboard-icon-64-green.png`；其他键继续使用文字。删除旧 `⏏` 字符和上下翻转动画。

### 光标

Codex TUI 会用 ANSI `CSI s` 保存输入光标，绘制同一行后续内容，再用 `CSI u` 恢复。当前备用屏只支持旧式 `ESC 7/8`，忽略 `CSI s/u` 后光标会停在最后绘制内容的末尾。本轮在已有 `saved` 字段上补齐 `CSI s/u`，不增加新状态。

### 横线折行

现有行数安全余量只解决纵向溢出。截图中的短横线是全宽分隔线超过 ArkUI 实际可用宽度后的横向折行。本轮保留少报一行，并增加固定的两列安全余量。该值作为物理字体度量校准常量保留，后续只有多设备实测不一致时再调整。

## 验证

- Rust 测试先构造 `CSI s/u` 失败用例，再验证光标恢复到已有输入末尾。
- ArkTS 干净构建验证系统输入法 API、图片资源和滚动属性类型正确。
- 模拟器覆盖安装后现场验证：手势上下滑动、离底不自动回底、键盘按钮反复显隐、图标外观、已有输入光标位置、横线不折行。

## 非目标

- 不实现完整主屏二维终端模型。
- 不更换终端渲染组件。
- 不增加可配置的行列安全余量界面。
