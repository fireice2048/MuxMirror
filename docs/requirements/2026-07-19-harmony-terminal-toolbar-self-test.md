# 鸿蒙 SSH 终端工具条全量自测与体验优化

## 背景

SSH 终端页双行工具条已完成首轮开发，但仍需在鸿蒙模拟器连接本机 SSH 后进行逐按钮实测，主动发现并修复功能或体验问题。历史上曾出现 KMM 代码已经修改、构建与安装均成功，但 HAP 仍携带旧版 `libkn.so` 的情况，因此本轮必须验证共享库实际入包和界面行为，不能只以构建成功作为结论。

## 目标

1. 编译并运行鸿蒙版 App，从首页点击第一项服务器并连接本机 SSH。
2. 连接成功后逐一验证终端工具条 20 个按钮：`/ - : * | HOME ↑ END PGUP DEL`、`ESC TAB PAST CTRL ALT ← ↓ → PGDN ⏏`。
3. 验证字符插入、光标移动、历史命令、翻页、删除、粘贴、修饰键和软键盘开关在真实 SSH 会话中的行为。
4. 自主发现并修复问题，优化终端页可用性、状态反馈和键盘联动体验。
5. `⏏` 在键盘收起时负责弹出键盘；键盘弹出后负责收起键盘，图标相对收起状态沿垂直方向翻转。

## 平台与验收环境

- 目标平台：HarmonyOS API 20+ 模拟器。
- SSH 目标：首页第一项，地址 `10.0.2.2:22`，连接本机 macOS sshd。
- 安装包：`entry-default-signed.hap`，使用 `hdc install -r` 覆盖安装以保留配置与凭据。

## KMM 共享库入包验收

1. 执行 `:composeUI:publishDebugBinariesToHarmonyApp` 发布 KMM/OHOS 共享库。
2. 在 `harmonyApp` 执行 `devecocli build clean` 后重新 debug 构建。
3. 对发布到鸿蒙工程的 `libkn.so` 与 signed HAP 内实际打包的同架构 `libkn.so` 计算 SHA-256；哈希必须一致。
4. 覆盖安装并稳定启动后，以终端页画面和交互结果确认新逻辑已经生效。

## 关键流程

1. 启动 API 20+ 模拟器并确认 `hdc` 在线。
2. 检查本机 `127.0.0.1:22` 的 SSH 密码认证前置条件，避免把 `AllowUsers` 限制误判为客户端缺陷。
3. 完整重打包、核验共享库入包、覆盖安装并启动。
4. 从首页第一项进入终端，确认 SSH 连接成功。
5. 逐按钮测试并记录预期、实际结果和证据；发现问题后补测试、修复、重新完整重打包并回归。

## 非目标

- 不修改本地终端页工具条。
- 不新增服务器配置或改变 SSH 凭据存储格式。
- 不以卸载重装作为常规更新方式，避免清空既有服务器配置和凭据。

## 待澄清问题

- 无；本轮按现有工具条定义和 xterm/zsh 常见行为进行验收。
