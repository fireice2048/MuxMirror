# 需求：鸿蒙原生终端显示与输入修复

## 背景

鸿蒙端继续使用 ArkUI `Text/Span` 原生终端，不回退到 WebView。当前备用屏 TUI 存在光标位置、弱化文字、屏幕行数、滚动历史和软键盘输入不同步问题，需要在现有 Rust 核心与 ArkTS 组件中修复。

## 目标

1. 正确显示备用屏光标，支持空白行、行尾空格和非 BMP 字符。
2. 将终端 ANSI 弱化文字显示为不明显的灰色，使待输入区 PlaceHolder 接近电脑终端效果。
3. 消除底部偶发多显示一行的问题。
4. 支持手势查看滚出屏幕的历史内容；用户上滑后保持当前位置，主动回到底部才恢复自动跟随。
5. 区分输入法预编辑文字与已提交文字：预编辑文字仅在终端输入位置本地显示，并暂时遮住 PlaceHolder；提交后立即发送到远端。
6. 软键盘 Backspace 能删除远端终端已有输入，不局限于删除本地输入缓冲。
7. 保留 ANSI 前景色与背景色，使 tmux/rmux 状态栏等显式配色区域能够高亮显示。

## 平台需求

- HarmonyOS NEXT ArkTS Stage 模型。
- Rust 核心同时支持 `aarch64-unknown-linux-ohos` 与 `x86_64-unknown-linux-ohos`。
- 保持当前 SSH/NAPI 会话接口，不改服务器协议。

## 关键流程

### 输出与样式

- Rust 终端缓冲继续解析 SSH 原始输出。
- 纯文本快照之外，上报 ANSI 弱化、反色、前景色、背景色样式区间和 UTF-16 光标偏移。
- ArkTS 使用 `Span` 渲染普通文字、弱化文字和显式 ANSI 配色。
- 渲染快照必须保留定位光标所需的空行和空格。

### 屏幕尺寸

- ArkUI 文本显式使用固定行高，PTY 行数采用同一行高计算。
- 上报给远端的行数预留 1 行安全余量，避免小数像素、内边距和字体度量差异造成底部溢出。

### 滚动

- Rust 备用屏保存实际滚出顶部的有限历史行。
- ArkTS 检测用户是否离开底部；离开后新输出不强制滚底，回到底部后恢复自动跟随。

### 输入

- ArkTS 从 `TextInput.onChange` 的 `previewText` 参数识别输入法预编辑文字，并从 `onDidInsert` 接收输入法最终确认文字。
- 预编辑文字只在本地光标处显示，不发往远端。
- 已提交字符和编辑按键立即写入 SSH 通道，由远端回显决定最终画面。
- 隐藏输入框保留可恢复的哨兵内容，使空输入状态下的软键盘退格仍能转换为远端 Backspace。

## 非目标

- 不引入 WebView、xterm.js 或新的终端 UI 框架。
- 不还原粗体、斜体、下划线、闪烁等与本轮状态栏高亮无关的 ANSI 字体样式。
- 不改变 PCServer 或 SSH 服务端行为。
- 不让预编辑文字提前写入远端。

## 验收标准

1. TUI PlaceHolder 显示为弱化灰色，输入预编辑文字时不被向右挤压。
2. 输入法确认文字后，电脑终端及时收到并回显。
3. 模拟器 Backspace 可删除电脑端输入的字符。
4. 终端底部没有偶发多余行；尺寸变化后仍稳定。
5. 可向上滑动查看历史，新输出不会抢走位置；滑回底部后恢复跟随。
6. 中文、emoji 和光标位于空白区域时不出现乱码或错位。
7. tmux/rmux 通过 ANSI 颜色绘制的页脚按指定前景色与背景色高亮，颜色复位后普通终端文字仍使用默认主题。

## 待澄清问题

无。

## 2026-07-22 现场补充反馈

1. Codex 终端仍无法用手势上下滑动，即使右侧已经出现滚动条。
2. 工具条键盘按钮无法重新弹起软键盘。
3. 键盘按钮直接使用用户提供的 `keyboard-icon-64-green.png`，不再使用 `⏏` 字符或翻转动画。
4. 连接已有输入内容的电脑终端时，模拟器光标可能停在文字尾部很远的位置；逐字删除后光标才逐渐靠近文字。
5. 全宽横线仍会折行，并在下一行左侧留下 1～2 个横线字符。

### 补充验收标准

- Codex 终端内容超过视口时，手指可直接上下滑动；停留历史位置时不被新输出拉回底部。
- 键盘按钮每次都能显式拉起或收起软键盘。
- 键盘按钮显示指定绿色 PNG，尺寸和其他工具键协调。
- ANSI `CSI s/u` 保存、恢复光标后，光标位于已有输入文字末尾。
- 横向分隔线不再折行残留；PTY 继续少报一行，并额外少报两列。

## 2026-07-22 物理键盘焦点与触摸滚动补充反馈

- 刚进入终端后，轻点终端内容区应让隐藏输入框获得焦点，使电脑物理键盘可以立即输入。
- 轻点终端内容区不得自动弹出软键盘；软键盘仍只由工具条键盘按钮显式拉起。
- 手指在终端内容区纵向拖动应滚动历史内容，轻点聚焦不得抢占拖动手势。
- 本轮优先保证滚动，不要求终端文本框选复制；粘贴继续使用工具条按钮。

## 2026-07-26 tmux/rmux 页脚高亮补充反馈

- 终端页底部的 tmux/rmux 状态栏文字已经能显示，但显式 ANSI 前景色和背景色被丢弃，导致页脚与普通输出同为绿字黑底。
- Rust 备用屏需解析 SGR 30–37、40–47、90–97、100–107，以及 38/48 的 256 色和 RGB 色，并通过 NAPI 样式区间传给 ArkTS。
- ArkTS `Span` 应以远端指定颜色渲染状态栏，同时保留现有弱化、反色和默认终端主题行为。

## 2026-07-26 终端状态栏底部留白补充反馈

- 手机端 tmux/rmux 状态栏与工具条之间存在明显黑色空白，电脑原始终端中状态栏紧贴视口底部。
- PTY 行数应按终端文本区域的真实可用高度计算，不再额外少报一行。
- Scroll 保留顶部与左右内边距，取消底部内边距，避免布局留白与少报行数叠加。
- 验收时对照同一 TUI 画面，状态栏应靠近终端容器底部，且顶部内容不整体下移、不出现额外折行。

## 2026-07-26 键盘与 MUX 窗口尺寸补充反馈

### 软键盘

- 点击终端工具条键盘按钮后，软键盘可能无法弹出。
- 普通终端页与 MUX 终端页会同时保留在页面 Stack 中；每个终端的隐藏输入框必须使用会话级唯一焦点 ID，避免导航后的按键请求命中已隐藏页面。
- 页面切换或输入法 client 脱离后，不能依赖缓存的 `hiddenInputFocused` 状态直接请求显示键盘；必须重新建立隐藏输入框焦点。
- 键盘显示请求失败或超时后应清除“正在请求”状态，保证下一次点击可以重试。

### MUX 尺寸与历史

- 手机连接现有 tmux/rmux 会话后，不得参与共享窗口尺寸计算，避免电脑端窗口被手机尺寸重排。
- attach 命令应为手机 client 启用 tmux 兼容的 `ignore-size` 标志；rmux 与 tmux 均使用其 `attach-session -f` 兼容接口。
- 当共享窗口高于手机 PTY 时，attach 后必须通过当前 SSH tty 精确定位手机客户端并将其可见区域下移到底部；不得使用未指定 client 的 `switch-client`，也不得改变电脑端 client 所在会话。
- 按目录分组查询必须在 UTF-8 locale 下执行，中文目录名应原样显示，不得被 tmux 转写为下划线或其他占位符。
- 手机 PTY 自身仍可随设备视口变化 resize，用于更新手机 client 的可见区域，但不能改写共享 MUX window 的逻辑尺寸；软键盘造成的临时高度压缩除外。
- 验收时手机进入已有会话后，导航页/电脑端报告的原始窗口尺寸应保持不变，电脑端历史内容仍可翻页查看。

### 光标位于行尾换行处

- TUI 输入框内使用上下方向键移动光标时，若远端光标落在一行末尾的换行符位置，覆盖式光标不得吞掉该换行符。
- 光标块应显示在当前行末尾，下一行（尤其 tmux/rmux 状态栏）仍从独立新行开始，不得与输入内容拼接后折成两截。

### 键盘弹出后的终端视口

- 软键盘弹出并压缩终端区域高度时，若用户原本正在跟随最新输出，终端必须在新布局完成后重新滚动到底部，使输入框和光标保持可见。
- MUX 终端在软键盘显示期间应保留键盘弹出前的 PTY 行数，让完整终端画面继续进入本地快照，再由手机端 Scroll 展示底部输入区；不得把远端 MUX client 裁成仅剩键盘上方的行数。
- 键盘弹出前若用户主动上翻查看历史，则不得强制抢回到底部。
- 键盘收起后同样应按当前跟随状态恢复视口，且终端区域仍可手势滚动查看历史。

## 2026-07-26 持续输出滚动与页面切换键盘补充反馈

- 终端持续输出期间，用户一旦在终端区域开始纵向触摸滚动，应立即暂停自动跟随；已经排队等待布局完成的滚底任务也必须取消或失效。
- 用户停留在历史位置时，后续输出不得抢回底部；用户主动滑回底部后恢复自动跟随。
- 从服务器终端首页点击「MUX...」或「返回」切换页面前，必须清除隐藏输入框焦点并主动收起软键盘。
- 后续页面不得继承前一个终端页面的键盘可见状态或失效的输入法焦点。
