# 鸿蒙全屏 TUI 远端回看需求

## 背景

鸿蒙 SSH 终端已经支持 ArkUI 本地滚动和有限备用屏历史，但 Codex 等全屏 TUI 会在备用屏内反复重绘同一视口。电脑终端的滚动条只能查看终端自身历史，鼠标滚轮则会作为终端鼠标事件发送给 Codex，由 Codex 自己切换其内部历史。因此，手机端仅滚动本地文本快照无法回看 Codex 隐藏的内容。

## 目标

1. 在手机和模拟器的远程终端中，通过双指纵向滑动回看 Codex 等支持鼠标滚轮的全屏 TUI 内容。
2. 保留现有单指本地滚动，用于普通 Shell 输出和终端自身保存的备用屏历史。
3. 双指手势不得触发终端点击聚焦、软键盘弹出或向远端发送普通字符。
4. 仅在远端应用启用终端鼠标跟踪时发送滚轮事件，避免普通 Shell 收到不可见转义序列。
5. 工具栏 `PGUP` / `PGDN` 在全屏 TUI 中提供按页远端回看，同时保留普通 Shell 下的本地翻页功能。

## 平台需求

- HarmonyOS NEXT ArkTS Stage 模型。
- Rust 核心同时支持 `aarch64-unknown-linux-ohos` 与 `x86_64-unknown-linux-ohos`。
- 继续复用现有 SSH `writeSession` 数据通道，不修改 PCServer 协议。
- 使用 ArkUI `PanGesture({ fingers: 2, direction: PanDirection.Vertical })` 识别双指纵向滑动。

## 关键流程

1. Rust 终端解析器跟踪 DEC 私有模式：
   - `?1000`、`?1002`、`?1003`：鼠标事件跟踪开关；
   - `?1006`：SGR 鼠标编码开关。
2. 每次 `output` 事件携带当前鼠标跟踪状态，ArkTS 终端组件据此决定双指滑动是否发送远端滚轮。
3. 双指滑动累计到固定阈值后，按方向生成滚轮事件；连续滑动可重复触发，单次更新限制最大事件数，避免快速手势产生输入洪峰。
4. SGR 模式发送 `CSI <64;列;行M`（向上）或 `CSI <65;列;行M`（向下）；兼容模式发送传统 X10 编码。
5. 滚轮坐标使用双指手势中心点换算后的终端行列，并钳制到当前 PTY 尺寸范围内。
6. 鼠标跟踪关闭时，双指手势不向远端发送数据；单指本地 Scroll 行为保持不变。
7. 工具栏 `PGUP` / `PGDN` 采用同一状态判断：鼠标跟踪开启时发送一页量的远端滚轮事件，关闭时继续调用本地 Scroller 翻页；不直接发送键盘 PageUp/PageDown 转义序列。

## 非目标

- 不把单指滑动改成远端鼠标滚轮。
- 不实现鼠标点击、拖拽选择或左右滚轮。
- 不改变 Codex、tmux/rmux 或远端 Shell 的配置。
- 不无限扩充客户端终端历史。

## 验收标准

1. Codex 全屏界面启用鼠标跟踪后，双指上下滑动可回看和返回其内部历史。
2. 普通 Shell 中双指滑动不会插入乱码；单指仍可回看本地输出。
3. Codex 中工具栏 `PGUP` / `PGDN` 可按页回看和返回；普通 Shell 中仍执行本地翻页。
4. 单指轻点仍可聚焦物理键盘输入，工具条键盘按钮行为不变。
5. 双指连续滑动响应平稳，不因一次大位移发送过量事件。
6. Rust 单元测试覆盖鼠标模式启停、组合模式和输出状态。
7. ArkTS 单元测试覆盖 SGR/X10 滚轮编码、坐标钳制和手势距离累计。
8. 双 ABI Rust 核心、签名 HAP 均构建成功，并在模拟器启动后现场确认功能生效。

## 待澄清问题

- tmux/rmux 是否会透传应用请求的鼠标模式取决于远端配置；若现场不能回看，需要结合电脑端同会话的滚轮行为和 tmux `mouse` 配置排查。
