# BugFix 记忆：持续输出抢回滚动位置与页面切换残留键盘

## 现象

- 触发条件：终端命令持续输出时手势上翻，或服务器终端页在软键盘打开时点击「MUX...」/「返回」。
- 用户影响：历史视口被后续输出反复拉回底部；键盘和旧输入焦点残留到导航页或服务器列表，影响后续页面布局与按键。

## 根因

- 输出快照更新时会根据当时的跟随状态排队滚底；用户随后开始滚动，已经排队的布局回调和键盘视口定时器仍会执行。
- 页面采用 `Visibility.Hidden` 保留终端组件，切页不会触发组件销毁；原按钮回调直接切页，没有先清除隐藏输入框焦点并等待输入法收起。

## 修复方案

- 涉及模块：`TerminalNativeView`、`TerminalPage`、`TerminalDisplayContract`。
- 关键改动：滚动开始即关闭跟随并取消所有待执行滚底任务，滚底回调执行前再次检查跟随状态；`blur` 改为可等待的异步操作，统一清焦和隐藏输入法，导航按钮等待完成后再切页。

## 验证方式

- 复现步骤：模拟器普通 SSH 终端执行 `ping 127.0.0.1`，持续输出中上翻；分别在键盘打开时点击「MUX...」和「返回」。
- 验证命令：`devecocli build --build-mode debug`，安装 `entry-default-signed.hap` 后用 `uitest` 操作并截图。
- 验证结果：上翻后数秒内视口稳定停留在 `icmp_seq=23–32` 的历史区间；导航页与服务器列表均恢复全高，输入法窗口不再残留。

## 预防措施

- 任何延迟或布局后的自动滚动都必须在执行时重新检查用户跟随状态。
- 使用隐藏页面保留组件实例时，页面切换不能依赖销毁回调清理焦点和输入法状态。
