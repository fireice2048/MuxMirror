# 踩坑记录：hdc uitest inputText 无法注入隐藏输入框

## 背景

- 日期：2026-07-17
- 场景：鸿蒙模拟器上验收 SSH 终端页"直接输入"改造（输入框改为终端区域内 1.dp 近透明 `BasicTextField`）。

## 坑的描述

- `hdc shell uitest uiInput inputText <x> <y> "<text>"` 的文本注入目标是**点击坐标处的输入组件**，而不是当前持有焦点的输入组件。
- 当输入框被刻意做成 1.dp / alpha 0.01 的隐藏组件（终端直接输入模式的常见做法）时，`inputText` 点击坐标落在终端显示区而非输入框上，文本静默丢失，命令返回 `No Error`，具有迷惑性。
- 现象：软键盘已弹出、焦点在隐藏字段上（IME 动作键正确显示"发送"），但注入的文本不进入输入缓冲，按钮保持禁用。

## 正确做法

- 自动化验收此类 UI 时，用 `uitest uiInput click <x> <y>` 逐个点击**软键盘按键**注入字符（走真实 IME 通道，必定到达焦点输入框），再截图核对输入缓冲渲染与按钮状态。
- 键盘按键坐标按截图相对位置换算绝对像素（截图原始分辨率 × 相对坐标）。
- 验证**物理键盘/按键事件**路径时，用 `hdc shell uinput -K -d <keyCode> -u <keyCode>` 在多模输入层注入（对照实验：浏览器地址栏可收到注入字母，证明该通道有效）；`uitest uiInput keyEvent <keyID>` 注入的按键不会到达应用按键分发，不能用于验证。
- 真机/手动输入不受此限制，该问题只影响 uitest 自动化。

## 影响范围

- 所有采用"隐藏输入框 + 自渲染终端文本"方案的页面自动化验收。

## 验证方式

- 点击软键盘 p/w/d 三键后截图：终端提示符后渲染出输入字符与光标，"发送"按钮由禁用变启用；点击"发送"后远端执行并回显结果（`zsh: command not found: pwf`，按键坐标偏移导致 d 误触为 f，属坐标换算误差，非应用问题）。
