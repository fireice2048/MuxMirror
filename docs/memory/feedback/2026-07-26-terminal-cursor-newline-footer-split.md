# BugFix 记忆：行尾光标吞换行导致页脚错位

## 现象

- 触发条件：在 TUI 输入框文字中间使用上下方向键移动光标，远端光标落到输入行末尾的换行符位置。
- 用户影响：tmux/rmux 页脚被接到输入文字后面，超出手机宽度的后半截折到下一行，看起来像页脚被切成两段并上下错位。

## 根因

- ArkTS 覆盖式光标会用反色字符或光标块替代光标位置的原字符，并从后续文本中跳过该字符。
- 当光标字符是 `\n` 时，旧逻辑也将其跳过，导致输入行与下一行状态栏失去换行分隔。

## 修复方案

- 涉及模块：`TerminalNativeView.ets`、`TerminalDisplayContract.ets`。
- 新增 `terminalCursorCharSkip`：普通字符仍由光标替代并跳过，换行符返回零跳过长度，保证下一行布局不变。
- 增加换行、空格、中文和 emoji 的跳过长度测试。

## 验证方式

- `devecocli build --build-mode debug` 构建通过。
- 模拟器连接独立临时 tmux 会话，构造输入行为 `> //---`、光标位于行尾、下一行紧接 tmux 状态栏的画面。
- 验证结果：光标保持在输入行末尾，状态栏完整位于下一行，没有拼接或二次折行。

## 预防措施

- 覆盖式光标不能把所有字符统一视为可替换的显示字符；换行等结构字符必须单独处理。
- 新增光标渲染变更时，至少覆盖普通字符、空格、换行、宽字符和代理对五类边界。
