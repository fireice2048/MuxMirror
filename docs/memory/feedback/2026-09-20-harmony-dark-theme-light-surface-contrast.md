# BugFix 记忆：鸿蒙深色主题下浅色界面白底白字

## 现象

- 触发条件：真机启用系统深色主题，进入使用固定浅色背景的首页、设置页或自定义编辑弹框。
- 用户影响：页面可能整体变暗；固定白色容器中的标题、输入文字、返回按钮和业务操作按钮会继承白色系统前景，造成白底白字或入口近乎不可见。

## 根因

- 页面同时使用固定浅色背景和未指定颜色的文字/图标，形成两套主题来源混用。
- `sys.color.ohos_id_color_primary` 在该深色主题设备上解析为白色，不适合作为固定浅色业务页面的品牌主色。
- 网络诊断输入框的占位色透明度过低，在黑色背景上对比不足。

## 修复方案

- 涉及模块：`MobileApp/harmonyApp/entry/src/main/ets/pages/`、`components/` 和颜色资源。
- 关键改动：
  - 固定浅色页面显式指定浅色背景、深色主文字和次要文字。
  - 新增在浅色/深色资源中值一致的 `app.color.brand_primary`，业务主操作不再依赖系统主题主色。
  - 自定义服务器弹框显式指定输入文字、占位文字、输入背景和按钮颜色。
  - 终端标题栏使用中性深灰文字，保留终端画布黑底配色。
  - 提高网络诊断占位提示对比度。

## 验证方式

- 复现步骤：真机保持深色系统主题，依次打开首页、新增/编辑、设置、SSH 终端、MUX 导航、网络诊断及确认弹框。
- 验证命令：`devecocli build --build-mode release`，随后使用签名 HAP 覆盖安装并启动。
- 验证结果：全部可达页面已逐屏截图检查通过，证据见 `docs/acceptance/2026-09-20-harmony-theme-contrast.md`。

## 预防措施

- 固定浅色容器内不得依赖系统默认前景色。
- 业务品牌色使用应用资源；仅在确实需要跟随系统语义时使用 `sys.color.*`。
- 新增页面或弹框需至少在系统深色主题下检查一次，确认背景、主文字、次要文字、输入框和操作按钮均可见。
