# 项目记忆系统

本目录用于记录开发过程和 BugFix 过程中的关键功能点、重点问题、技术决策和排查结论，帮助后续开发快速恢复上下文。

## 目录结构

- `features/`：记录新增功能、核心能力、重要接口和行为变化。
- `bugfixes/`：记录 Bug 现象、根因、修复方案、验证方式和预防措施。
- `decisions/`：记录架构、依赖、协议、模块边界等重要技术决策。
- `issues/`：记录未解决问题、风险、坑点和后续待办。
- `templates/`：记录模板，新增记忆时优先复制模板。

## 命名规范

文件名使用日期加简短主题：

```text
YYYY-MM-DD-short-topic.md
```

示例：

```text
2026-07-07-session-reattach-design.md
2026-07-07-mobile-keyboard-input-bugfix.md
```

## 记录时机

以下情况必须新增或更新记忆：

- 新增关键功能或改变核心行为。
- 修复影响用户使用、连接稳定性、终端交互或数据安全的问题。
- 做出重要技术选型或架构取舍。
- 发现容易重复踩坑的问题。
- 引入新的运行、测试、发布或调试流程。

## 记录原则

内容应短而具体，优先记录可复用结论。避免流水账；不要记录密钥、令牌、密码、私钥、用户隐私或完整日志。必要日志只保留关键片段，并脱敏处理。
