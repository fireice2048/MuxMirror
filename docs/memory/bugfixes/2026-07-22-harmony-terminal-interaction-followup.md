# BugFix 记忆：鸿蒙终端滚动、键盘与光标补充修复

## 现象

- 触发条件：在鸿蒙模拟器连接电脑端终端，使用触摸滚动、工具条键盘按钮，或接入已经存在待输入文字的备用屏会话。
- 用户影响：终端无法上下滑动；键盘按钮无法再次拉起软键盘；电脑端已有输入时移动端光标偏右；满宽分隔线可能在下一行残留少量横线。

## 根因

- 终端外层点击手势与 `Scroll` 的拖动识别冲突，导致纵向滚动没有稳定接管触摸事件。
- 隐藏输入框已经持有焦点时，重复请求焦点不会主动显示已收起的输入法。
- Rust 备用屏只支持 `ESC 7/8` 光标保存恢复，未处理现代 TUI 常用的 `CSI s/u`，光标因而停在后续占位文本末尾。
- PTY 列数直接按理论字符宽度取整，字体度量和 ArkUI 实际布局的微小误差会使服务端输出比可视区域多一两列。

## 修复方案

- 涉及模块：`MobileApp/shared` 终端解析器、HarmonyOS 原生终端视图和工具条。
- 关键改动：补齐 `CSI s/u`；显式启用纵向滚动并移除冲突点击手势；键盘按钮在请求焦点后调用 `showTextInput()`；PTY 列数保留两列安全余量；直接使用用户指定的绿色键盘 PNG。

## 验证方式

- 复现步骤：连接 ProbeServer，输出 1～100 后上下滑动；停留在历史位置时继续输入；反复点击键盘按钮；输出与 `tput cols` 相同数量的横线。
- 验证命令：`cargo fmt --all --manifest-path MobileApp/shared/Cargo.toml -- --check`、`cargo test --manifest-path MobileApp/shared/Cargo.toml`、`bash MobileApp/shared/scripts/build-ohos.sh`、`devecocli build clean`、`devecocli build --build-mode debug`。
- 验证结果：Rust 59 项测试全部通过；双 ABI 与签名 HAP 构建、覆盖安装成功；模拟器现场确认滚动、离底保持、键盘反复拉起和图标生效；PTY 为 45 列时，45 个横线保持单行且下一行无残留。

## 预防措施

- 新增 ANSI 光标控制序列时同时覆盖普通屏与备用屏的光标位置测试。
- PTY 尺寸由文本实际度量结果计算时保留小幅列安全余量，并用满宽字符现场验收。
- 隐藏输入框驱动软键盘时，不把“获得焦点”等同于“输入法已经显示”。
